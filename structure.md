### Tables defined in `install.xml`

| Table | Purpose |
|---|---|
| `local_lid_settings` | Site-level and course-level LLM config, prompt template, prompt lock flag |
| `local_lid_forum_config` | Per-forum enable/disable, optional prompt override |
| `local_lid_analysis` | One row per analysis unit (post / forum / student-forum / course) |
| `local_lid_queue` | Analysis job queue with priority, retry counter, timevisible |

## `/prompts/` — Default prompt templates (shipped with plugin)

```
prompts/
├── default-session-analyzer.md    ← LID session analyzer prompt v1.0 (canonical default)
└── forum-post-preamble.md         ← Context preamble injected for forum post content
```

> **How the default prompt works:**  
> On first install, `session_analyser.php` reads `prompts/default-session-analyzer.md` and writes
> it to `local_lid_settings` as the site-level `prompt_template`. From that point forward, the DB
> value is the source of truth. The file is never read again after install unless an admin
> explicitly resets to default.

- `develop` — integration branch
- `feature/phase-1-foundation` — current work branch
- Feature branches merge to `develop` via PR; `develop` merges to `main` on release
